# dsh-all-in-one

DeepSeek Harness 的「一站式」插件：把一些彼此独立的小工具收进设置里的同一个网格，
需要哪个就点哪个，不必为每个小功能单独安装一个插件。

## 在哪里使用

安装后打开 **设置 → All In One**，会看到三块四行的网格，每块四项：

- **对话体验**：一条对话内的阅读与操作；
- **界面布局**：侧边栏、会话列表与导航结构；
- **配置与维护**：带参数或配置页、在后台生效的功能。

每块里每个格子是一个功能。页面型功能点卡片进入独立页面，卡片右下角另有「设置 ›」入口
（技能包、项目记忆这两张卡片右侧还各有一个开关）；开关型功能只有卡片右侧的开关可以拨动，
点卡片其余位置不会改变状态，也没有这个入口 —— 凭它就能看出哪些格子点得进去。

## 功能

| 分组 | 功能 |
|---|---|
| 对话体验 | 展开过程、会话图片预览、清空会话、编辑排队消息、全自动执行 |
| 界面布局 | 会话历史左侧、菜单收进更多、项目会话数、删除会话 |
| 配置与维护 | 技能包、项目记忆、自动压缩会话、Cookie 清理 |

前两组的功能切换后都会刷新页面，因此网格在分组标题旁统一标注「切换后刷新生效」，
卡片里不再逐张重复；「配置与维护」里的开关改完即时生效，不需要刷新。

下面按功能逐个介绍。

### 技能包

让不同的对话使用不同的技能、插件与 MCP 服务器，而不是所有对话共用同一套能力。

技能包受卡片右侧的开关控制，**默认关闭**。先在「All In One → 技能包」里创建技能包，
再回到网格把开关拨开；关闭时新建对话界面不再出现「技能包」下拉，也不能再叠加技能包，
**已经开始的对话保持原样**。一个技能包都没有时，开关无法打开。

在「All In One → 技能包」里新建技能包，可以为它配置：

| 配置项 | 作用 |
|---|---|
| **技能** | 选择这个技能包能用哪些技能，支持「全部 / 仅应用 / 仅排除」三种规则 |
| **插件与工具** | 在所选模式的基础上保留或剔除终端、文件读写、检索、子智能体等工具；已装插件也在同一列表里取舍 |
| **MCP 服务器** | 只决定已安装的 MCP 服务器是否在本技能包的会话里生效；服务器本身在宿主的配置文件里声明 |
| **系统提示词** | 追加一段要求到系统提示词末尾，约定这个技能包的工作方式 |

**新建对话时**，输入框上方有两个独立的下拉：

- **模式**：标准、PTC、极简、创造等宿主自带模式，决定基础工具与提示词；
- **技能包**：你创建的技能包名称。

两者不是二选一。先由模式提供一整套基础能力，再由技能包在此基础上筛选技能与工具、
屏蔽部分 MCP 服务器、追加系统提示词。例如「标准模式 + 代码审查技能包」= 标准模式的全部工具，
只保留代码审查需要的技能，并追加审查规则。选中同一个技能包再次点击可取消，回到纯模式运行。

在技能包列表里点「设为默认」，可以把某个包设为新建对话的默认预选：之后的新对话会自动
选中并应用它，仍然可以随时切换成别的包或取消。

> 技能包只能用于**新对话**。对话一旦开始就不能再切换，这是宿主为避免工具集与历史记录
> 不一致而做的限制。

技能包配置保存在 `$DSH_HOME/all-in-one/power-packs.json`，不随插件升级丢失；
从旧版本升级时会自动迁移原有配置。

#### 会话级隔离是怎么做到的

宿主的组合分两层，技能包只作用在第二层：

| 层 | 何时加载 | 技能包能否改变 |
|---|---|---|
| **全局层** | 进程启动（profile 的 `bundles`、`$DSH_HOME/cordis.patch.yml`） | 只能屏蔽，不能卸载 |
| **预设层** | 技能包 + 模式合成预设后，挂在**预设作用域** | 完全由技能包决定 |

预设层里的每一行（技能目录、`skill` 工具、提示词段）都按作用域注册，
只对绑定该预设的会话可见，这就是技能包天然会话级生效的原因。

全局层里的插件（例如 `dsh-purge`）在启动时就把工具和提示词写进了全局注册表，
预设无法把它们卸载。技能包用两件事把它们从会话里摘掉：

1. **工具掩码**：预设里有一行隔离插件，按被排除的能力调用宿主的
   `tools.restrict({ deny })`。掩码挂在该预设作用域上，因此只有该会话看不到这些工具
   （包括 `mcp__<server>__*` 形式的全局 MCP 工具）。
2. **提示词隔离**：同一行监听装配 waterfall。排除已装插件时它先取一份装配快照，
   等下游（全局注入器）改完后再把段落还原成快照，模型只收到本技能包声明的提示词；
   只按插件名前缀删段是兜底路径。运行上下文（工作目录等）始终保留下游结果。
   有些全局插件（如 dsh-purge）还会把 `systemPrompt.assemble` 方法本身包一层，
   在装配返回后再改写——这条路径不经过事件，因此宿主侧另有一层最外层包装，
   按「这个会话是否记录了快照」决定要不要还原，未启用严格隔离的会话不受影响。

已装插件与全局 MCP 不需要额外板块：它们直接出现在「插件与工具」和「MCP 服务器」的
三态列表里，和标准工具行共用同一套「全部 / 仅应用 / 仅排除」规则。
勾选表示**保留**在技能包会话里，取消勾选表示**屏蔽**。

MCP 服务器只在宿主的配置文件（设置页的「打开配置文件」）里声明，启动时由宿主连接；
技能包不保存服务器定义，因此同一台服务器只需要配置一份，多个技能包各自决定要不要它。

列表由宿主侧扫描得到：工具注册表的全局视图给出实际存在的工具名，已装插件再用包名
前缀与构建产物交叉确认归属，全局 MCP 按 `mcp__<serverName>__` 前缀分组。

> 限制：预设无法阻止全局插件在宿主进程里做的非会话副作用（后台定时器、写文件、
> 自己启动的子进程等）。要让它彻底不生效，只能从 profile 的 `bundles` 里移除该插件
> 并重启宿主；此时它对所有会话都不再加载。

### 删除会话

宿主的会话列表只提供「归档」——归档只是把会话从列表里藏起来，历史记录仍然留在磁盘上。
这个开关打开后，每条会话行的悬停操作里会多出一个垃圾桶按钮，工作区「更多」菜单里
会多出一项「删除所有会话」；两种入口都先在弹窗里确认，确认后才删除本地历史。

- 位置与宿主自带的归档、置顶按钮一致（鼠标移到会话行右侧即可看到）；
- 「删除所有会话」位于工作区「更多」菜单里「重命名」之后、「删除工作区」之前，
  一次清掉该工作区里所有不在运行中的会话（含已归档会话），不必逐条删除；
- 弹窗里会写明要删除的会话标题（批量删除时是工作区名与待删条数）以及删除范围，
  取消则不做任何改动；
- 弹窗打开时焦点落在「删除」按钮上，直接按回车即确认删除；
- 删除不可撤销，确认后会话行随之消失；宿主拒绝时原因会留在弹窗里，可直接重试；
- 正在运行的会话不显示删除按钮，批量删除也会跳过它们，避免打断正在执行的任务；
  当前正在浏览的对话可以删除，删除后优先切到该工作空间里进行中的任务，
  没有进行中的任务则切到第一条对话，该工作空间一条对话都不剩时打开新建对话页面；
- 批量删除时若有会话删不掉，弹窗会保留并提示失败条数，关闭后重新操作即可；
- 工作区里没有可删的会话时，菜单项不出现；
- 拨动开关后页面会自动刷新，入口随即出现或消失。

> 删除清除磁盘上的本地会话数据：会话目录（对话正文）、标题等投影缓存，以及工作区
> 排序与归档集合里的该会话 id。搜索索引由宿主在下次查询时自行剔除。
> 不涉及工作目录里的任何文件。

### 清空会话

宿主没有「把一条对话的历史清零后继续用」的能力——会话日志是只追加的，删不掉中间部分。
所以这里的做法是换一条新对话：在同一工作区打开一条空白会话，原对话的去向由你在弹窗里选。

- 入口是输入框左下角、加号按钮左边的圆形按钮（圆环中一条横线），悬停显示「开启新会话」；
- 点击后弹出标题为「开启新会话」的确认框：取消在左下角，右下角是「直接开启」与「删除本次会话」两个动作；
  - **取消**：关闭弹窗，什么都不做；
  - **直接开启**：在同一工作区开一条空白对话，当前会话原样保留在会话列表里，不归档也不删除；
  - **删除本次会话**：开新对话的同时，删除当前会话的本地记录（不可恢复）；
- 弹窗打开时焦点落在「直接开启」上，直接按回车是安全动作，不会误删；
- 两个动作都是先切到新的空白对话，删除动作再处理原对话，界面不会停在一条已经不存在的会话上；
- 当前会话正在执行任务时：**直接开启**完全不管它，它在后台继续跑完，你直接到新对话里干活即可；
  **删除本次会话**会先自动中断那一轮，等它真正停下再删；万一 8 秒内没停下，会明确提示任务未能及时停止，
  不会带着运行中的会话往下走；
- 已经在空白的「新会话」页面时，不会产生多余的空白会话；
- 拨动开关后页面会自动刷新，输入框旁的按钮随即出现或消失。

> 「删除会话」清除的是磁盘上的本地会话数据（与「删除会话」功能同一套清理范围）：
> 会话目录（对话正文）、标题等投影缓存，以及工作区排序集合里的该会话 id。
> 工作目录里的文件不受影响。

### 编辑排队消息

Agent 正在跑的时候提交的消息会先排队，等这一轮结束才发出去。排队条上的编辑按钮
默认只能改文字，带图片的消息连改都改不了；想改内容就只能删掉重新输入一遍。

打开这个开关后，排队条上的编辑按钮改成「撤回并编辑」：

- 点击编辑，这条排队立刻撤回，文字与图片一起回到输入框，改完直接回车重新发送；
- 输入框里原有的文字与图片会被清空，让位给这条排队的内容；
- 撤回先写输入框、再删排队，所以输入框正在发送新消息时不会撤回，排队原样保留；
- 带文件附件（非图片）的排队消息无法回填，点击时会提示改用删除后重新添加；
- 拨动开关后页面会自动刷新，排队条上的编辑按钮随即换成新的行为。

### 展开过程

控制会话里的「思考」与「运行命令」是否默认展开。

在网格中拨动开关后页面会自动刷新，之后新出现的思考与命令块都按新状态显示；
已经渲染过的旧内容也会随刷新一起按新状态展示。

开关打开后，卡片下方多出一行「展开范围」，二选一决定展开到哪些过程：

- **全部对话**：所有轮次的思考与命令块都展开，翻看完整过程最直接；
- **最新对话**：只展开最新一轮对话的过程，历史轮次保持折叠；这一轮结束后过程
  保持展开，直到你提交下一条提示词、新一轮开始时才折叠。

「最新对话」按轮次判断：一轮从你主动提交的提示词开始算，轮内 agent 的提问与你的
回答仍属于同一轮，不会因此折叠；同一轮里已经跑完的步骤也保持展开，方便回看这一轮
做过什么。手动点开的任意一行由你掌控，插件不会再替你折叠。

这一档不受宿主「工作步骤收起时机」设置影响：宿主默认在回答结束后就把完成轮的过程
收成摘要，本模式按「下一次输入后」处理，所以最新一轮跑完仍然展开，只有你提交下一条
提示词、开始新一轮时才收起。「全部对话」不改变宿主该项设置。

开关打开时，思考与命令行标题使用主文字色，展开后的过程内容向右缩进 20px，
并在内容左侧显示一条浅灰竖线，用来区分「行标题」与「过程内容」两级；
单行仍可随时点击折叠。

> 不要与独立的 `dsh-plugin-expand-process` 插件同时启用：两者改写同一段界面代码，
> 会把展开状态写死为开启，导致本开关失效。迁移到本插件后请移除独立插件。

### 会话图片预览

会话里出现本地图片地址时，在地址下方直接显示图片预览，不用再手动去文件管理器里找。

在网格中拨动开关并刷新页面后：

- **自动识别**会话正文中的本地图片路径：`/Users/…/shot.png`、`file:///Users/…/shot.png`、
  `~/.dsh/…/shot.png` 等形式，支持 png、jpg、jpeg、gif、webp、bmp、avif、svg 与 ico；
- 另外识别**宿主附件库**里的对象文件（`~/.dsh/attachments/v1/objects/<两位>/<64 位哈希>`）：
  这类文件没有扩展名，按文件内容判断类型。宿主的附件库**永不被自动清理**，
  所以这里的图片会一直显示，不会像 `/tmp` 里的临时图那样删掉就没了；
- 工具只回了**附件 ID**（`sha256:<64 位哈希>`，如 chrome-devtools MCP 的截图结果）时，
  同样会解析到附件库并显示预览，不需要工具额外提供文件路径；
- 系统截图、MCP 工具或脚本把图片保存到本地后，只要路径出现在会话里，就会在路径下方看到缩略图；
- **点击会话里的任意图片都能放大**：本功能插入的预览图与宿主自己渲染的图片（上传的附件、
  工具输出截图、Markdown 图片）用的是同一个放大层，不再出现两套样式；放大层右上角常驻
  关闭按钮，点遮罩或按 Esc 也能关闭；
- **放大层支持缩放**：滚轮以光标为中心缩放，底部工具栏提供「−」「百分比」「+」、
  「1:1 原始大小」与「适应窗口」，放大后按住图片可拖动查看局部，双击在适应窗口与原始大小
  之间切换；键盘 `+` / `-` 缩放、`0` 适应窗口、`1` 原始大小；
- 相对路径（如 `artifacts/a.png`）与非图片路径不会触发预览，避免误识别普通文本；
- **只读预览**：不修改会话内容，不移动、覆盖或删除任何文件，也不介入工具的保存与清理流程；
- 文件已被删除或内容不是图片时，刷新页面后预览自动消失，不会反复重试；
- 已显示出来的预览不会主动轮询文件：删掉图片后，刷新前那一份仍来自浏览器内存，
  刷新一次即可确认文件是否还在（本功能不做任何文件操作，也不监听文件系统变化）；
- 关闭开关并刷新页面后不再插入任何节点；只在会话正文区域生效，侧边栏、设置页与其它界面不受影响。

> 图片由插件的本地只读接口读取：只允许本机访问；常规图片只接受绝对路径与图片扩展名，
> 附件库对象只接受 `<DSH_HOME>/attachments/v1/objects/` 下按内容哈希命名的文件（可用
> 附件 ID 请求，由宿主换算成该路径）。浏览器端不直接接触文件系统。

### 会话历史左侧

对话右侧那一列「跳转到第 N 轮」的横杠，默认停在右侧。打开本功能后它挪到对话左侧，
点击跳转的用法完全不变——只是换了位置，宿主的导航逻辑一点没动。

入口是「会话历史左侧」开关，打开后导航条移到左侧。

细节：

- 悬停预览照常工作：预览卡跟着挪到横杠右侧，仍是宿主的实现；
- 关闭开关并刷新页面后，导航条回到右侧，插件不留下任何样式或节点。

### 菜单收进更多

侧边栏顶部那一组入口（插件、Skill / MCP、自动化任务、更多）占着「新会话」下方一排的位置。
打开本功能后，这一整块收起，其中的入口按原顺序搬进左下角的「更多」菜单，
和设置、意见反馈排在一起，点击行为保持不变。

入口是「菜单收进更多」开关，打开后刷新页面生效。

细节：

- 搬运的是入口本身：点「插件」仍然打开插件面板，点「自动化任务」仍然打开任务面板；
- 顶部的「更多」展开后是「浏览更多插件 / 创建你的插件」，这两项也直接列进底部菜单，
  不需要再点开一层；
- 宿主没有对应入口时（例如当前版本没有 Skill / MCP 项）自动跳过，不影响其它项；
- 账户项（登录 / 退出登录）之后还有一项「All In One」，点它打开设置弹窗并直接落在
  本插件的设置页，不必先打开设置再从左栏翻找；
- 关闭开关并刷新页面后，顶部恢复原样，底部菜单不再插入任何节点。

### 项目记忆

让对话记住项目里那些「代码里看不出来」的事：用户的偏好、既往的纠正、项目的约定与
正在进行的工作。打开后：

- 每个项目有一份记忆，**记忆索引（`MEMORY.md`）在每次对话中自动进入上下文**；
  助手需要某条记忆的细节时按名读取全文——记忆再多也不会把上下文占满；
- 对话里说「请帮我记住……」，或者你在对话中纠正了做法，助手会把要点写进记忆文件，
  同一轮对话的后续消息即可带上新的索引；
- 记忆**按项目隔离**：同一个项目下的所有对话共享一套，不同项目互不干扰。

记忆的文件格式与 **Claude Code 完全一致**（`MEMORY.md` 索引 + 每条记忆一个 Markdown
文件，字段为 `name` / `description` / `metadata.type`，正文用 `[[其它记忆名]]` 互相引用）。
把记忆根目录指向 `~/.claude/projects`，dsh 与 Claude Code 就共用同一套记忆：
在 Claude Code 里记下的事，dsh 里照样能看到，反之亦然。

在网格里拨动卡片右侧的开关即启用；点**卡片本身**进入「记忆路径」页面，在那里改记忆根目录：

| 设置 | 说明 |
|---|---|
| **记忆根目录** | 留空使用插件默认目录（`$DSH_HOME/all-in-one/projects`）；填 `~/.claude/projects` 与 Claude Code 共用 |
| **当前使用** | 实际生效的目录；填了不可用的路径时会回退到默认目录，这里能看出来 |

记忆名为 kebab-case（小写字母、数字、连字符），例如 `dsh-plugin-project`。
每条记忆的落位是 `<根目录>/<项目路径编码>/memory/`，与 Claude Code 的目录映射规则相同。

> 记忆是给模型看的背景事实，不替代项目里的 `AGENTS.md`：后者是团队共享的仓库内约定，
> 记忆则是这台机器上这个人积累下来的经验。

### 全自动执行

让某个对话从头跑到尾都不来打断你：不提问、不等确认、改完自己验证。

入口是输入框右侧的「全自动」开关（文字 + 滑动开关，排在模型选择器与「回退」之前），
**按会话生效**：A 对话打开不影响 B 对话，新对话的初始状态由设置页的「默认值」决定。开关打开即表示当前对话处于自动模式，
同时侧边栏该会话标题前会出现一枚窄长条闪电标识（9×16px，警示黄），一眼看出哪些对话在自动跑。
标识插在标题文字之前，宿主的转圈、询问黄点、完成绿点仍由宿主绘制，两者互不影响：标识按实测
重叠量把状态点整体左移让位（只挪重叠的那几像素，不动布局），位移由行上的 CSS 变量驱动，宿主
重建转圈节点也依旧生效，不会压住转圈；标识本身用负外边距抵消占位并实测校准，与标题距离 2px，
会话标题的缩进与没开全自动的会话完全一致。

开启后，宿主会在系统提示词末尾为本会话追加一段约定，模型因此：

- 不调用 `ask_user_question`，也不以「请选择 / 请确认 / 是否继续」结束回复；
- 需要方案取舍时按「会话指令 > 项目约定 > 最小可逆做法」自行定夺，直接执行；
- 改完自己编译、运行、自检，失败就自己修，不再弹出验证方式让你选；
- 只有缺少凭据或权限、外部服务不可用这类不可恢复的阻塞才在回复里说明并结束。

**询问工具在自动模式下直接禁用**：`ask_user_question` 的调用会在执行前被拦下，返回一句
「本会话不允许向用户提问」的理由让模型自己继续，因此不会渲染出任何提问框——不是「弹出来
再自动替你选」。一个作用域级应答器仍保留作兜底，万一询问走到服务层也会立刻作答。
**权限审批类询问一律放行**——自动模式代替的是「选择与确认」，不代替「授权」；这类询问
仍会停下来等你点。

关闭开关后一切恢复原样：该问的照问、结束时的验证流程也照旧，侧边栏标识同步消失。
设置页里的开关是功能的总入口，决定是否安装这两处入口（默认显示），切换后刷新页面生效；
隐藏开关不会替你关掉已经开启的会话，要停用请先在对话里点灭。

卡片下方的「默认值」决定新对话的初始状态（切换后刷新页面生效）：

| 选项 | 新对话的初始状态 |
|---|---|
| **默认关** | 一律关闭，这是默认选择 |
| **默认开** | 一律开启 |
| **上一次** | 沿用最近一次切换后的状态 |
| **工作空间** | 沿用所属工作空间最近一次的状态 |

默认值只作用于还没有显式记录的对话；手动点过开关的对话始终以它自己的记录为准。

> 配置保存在 `$DSH_HOME/all-in-one/auto-run.json`：显式开关按会话记录（最多 200 条），
> 工作空间最近的状态按工作空间记录（最多 100 条），另外保存默认值来源与最近一次状态。
> 自动模式不改变权限策略：它追加行为约定，并禁用询问工具。

### 自动压缩会话

会话上下文占用达到阈值时，把**较早**的历史压成摘要，**最近**的对话逐字保留，长对话不会越聊越慢。

打开开关后，卡片下方会出现两个输入框，都按**上下文窗口占用百分比**填写：

- **阈值**（1-100，默认 80）：占用达到这个比例才压缩；
- **保留**（整数，且必须小于阈值，默认 16）：压缩后上下文的**总占用**目标比例。工具定义这类不随压缩变化的开销会先被扣除，剩余预算按真实 token 换算成要逐字保留的历史。

触发时机是每一步派发模型请求之前，所以回合中途也会压缩，不必等整轮结束：

- 压缩范围从最早的历史开始，到「保留」预算够用为止，最近若干轮始终逐字保留；
- 切点会避开工具调用与结果之间，不会拆散一次调用；系统提示词永远不进入压缩范围；
- 压缩走宿主的分段压缩事务，与手动压缩同一套机制，摘要失败时本轮照常继续；
- 工具定义等固定开销本身就超过「保留」比例时，压缩会压到最小尾部，并在宿主日志里说明该目标不可达；
- 阈值建议低于宿主内置的 80% 自动压缩线；留在 80% 时两者行为基本一致；
- 开关与两个比例保存后立即生效，不需要重启宿主。

> 配置保存在 `$DSH_HOME/all-in-one/auto-compact.json`。上下文窗口与占用由宿主的
> token 统计提供，模型未报告窗口容量时不会触发压缩。

### 桌面版 Cookie 清理

桌面版每次启动都会用随机端口生成一个新的认证 Cookie（`dsh-auth-<端口哈希>`），旧记录
既不过期也不被覆盖。攒到几十条后，桌面版会在欢迎页报认证失败、窗口打不开。

这个功能默认开启，在宿主启动阶段（早于桌面版做欢迎认证）清掉更早的认证 Cookie。
打开开关后，卡片下方会出现两个输入框：

- **阈值**（1-100，默认 3）：认证 Cookie 达到这个条数才清理；
- **保留**（整数，且必须小于阈值，默认 1；填 0 表示全部删掉）：清理时保留最近的几条。

只删除桌面版 cookie 库里 `dsh-auth-*` 的记录，同一个库里的其它 Cookie 不受影响；
浏览器里的 Web 开发环境用的是自己的 Cookie，不会被误清。

> 配置保存在 `$DSH_HOME/all-in-one/desktop-cookie.json`。
> 如果某次启动已经卡在欢迎页，启动清理要下一次启动才生效，重新打开一次应用即可。

## 兼容性

- 插件遵循宿主主题，自动跟随明暗模式，不写入固定颜色。
- 各功能互不影响：某个功能配置不完整时会被自动跳过，不影响其它功能的使用。
